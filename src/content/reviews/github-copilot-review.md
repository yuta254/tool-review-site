## 総評

GitHub Copilotは「ゼロから書く」よりも「途中から続きを書く/定型処理を自動補完する」場面で真価を発揮するツールです。

## 得意なこと

- テストコードのひな形作成
- 既存コードと似たパターンの繰り返し実装
- 見慣れない言語・フレームワークでの書き方の参考

## 過信は禁物な点

- 生成されたコードをそのまま鵜呑みにせず、必ずレビューする前提が必要
- セキュリティやライセンスに関わるコードは人間の最終確認が必須
- 学習目的で「自分の手で書く力」を伸ばしたい初学者は、頼りすぎに注意

## 向いている人

- 普段からエディタ(VS Code / JetBrains系)で開発している人
- 定型的なコードやテストを書く頻度が高い人
- 一人で開発していて、レビュー役が近くにいない人

## 使い方のコツ

1. まずは個人アカウントの無料トライアルで自分の開発スタイルに合うか試す
2. チーム導入の場合は、コードレビュー運用にAI生成コードのチェック項目を追加する
3. 補完を「採用するかどうか」を都度選べる操作に慣れておく

チーム全体での利用を検討する場合は、[AI API料金計算ツール](/tools/ai-api-cost-calculator/)で人数分の想定コストを事前に試算しておくと予算感がつかみやすくなります。

料金プランや対応エディタの詳細は変更される可能性があるため、公式サイトで最新情報を確認してください。

## よくある質問

**Q. 実際にどれくらい速くなりますか。**
定型的なコード(テスト、ボイラープレート、既知のAPI呼び出し)ほど効果が大きく、設計判断が要る部分ではほとんど変わりません。「全体が何割速くなる」より「どの作業が消えるか」で見たほうが導入判断を誤りません。組織で導入効果を数字で確かめる方法は[GitHub Copilotの導入効果を測る方法](/reviews/github-copilot-impact-measurement/)にまとめました。

**Q. 提案されたコードをそのまま使って問題ありませんか。**
動くコードが出てくることと、正しいコードであることは別です。特に境界値の扱いとエラー処理は補完が甘くなりやすく、レビューを省略すると後で効いてきます。

**Q. 会社のコードを学習に使われませんか。**
ビジネス向けプランでは、入力内容を学習に使わない設定が提供されています。ただし既定値はプランによって異なるため、導入時に管理者が明示的に確認する必要があります。個人プランを業務で使う場合は特に注意してください。
